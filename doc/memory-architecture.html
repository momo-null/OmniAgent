OmniAgent 记忆架构

2026-11-14 · 与 doc/plans/implemented/memory-architecture.md 及分支 feat/vector-recall 现行实现同步 · 写链总纲：事件 → 助手的取舍 → 记忆

总览一张图看全部

记忆系统分四层（L0→L3）加三条侧翼资产。所有写入只能经内核发生；助手的行为权 通过工具代理；世界事件一律先落 L0，成为「助手的记忆」必须经过一次助手的动作或巩固期的内化。

写链总纲2026-11-10 定稿

早期的写法是给每处判断真空都补一道代码门。后来原则收敛成一句话： 约束应当是显式可见的常识，而不是看不见的钳夹。

要点收尾零提炼（严格 L1）

任务收尾 flush_brain 不再自动蒸馏原子——只做语境链、关系卡（L0 直驱）、 L2 维护、巩固调度。旧「对话直接提炼 L1」会把助手执行任务的路径细节当规则收进事实库 （2026-11-09 实证 9 条全废）。

要点allow_atoms 已退场

「按来源一刀切」的记忆准入开关整删。防投毒的正确防线 = 事件取舍 + source_external 结构信号 + 升格门槛。禁止任何「换个枚举名还是一刀切」的伪替代。

L1 · 原子记忆

brain.db · atoms（active 44 / tombstone 25 @2026-11-13）。project 只是 origin 溯源标签，不是分区键；persona 冻结恒空；owner 列已 DROP。

三条生长路径（严格 L1）

检索排序（融合公式）

rel   = bm25_rank_to_score(rank) = (-rank)/(1+(-rank))     # 绝对分，非候选集内归一
final = 0.55·rel + 0.30·importance + 0.15·exp(-days/180)
peer 命中 ×1.25（加权不过滤）│ 最近环内 ×0.85（只降权）
同场合 ×(1+0.25) │ 圈层话题词面 ×(1+0.10)                    # INV-3 加权不过滤
final < 0.30 → 丢；去冗余 (kind, peer, content[:12])；轮换环 64；top_k = 5

向量通道（见 召回与向量臂）是并列候选源：向量专属行 rel = max(0, cos) 进同一公式；FTS 行 rel 一律 bm25 原值，逐值不变。

观察升格（巩固 7.5 步）

promote_observations 是「助手记的见闻」内化成「助手记得的事实」的唯一通道：

  • 取未升格且 source_external = 0 的观察行（外部可达来源的见闻永不升格——投毒锁）；
  • LLM 逐条提炼成 ≤60 字结论短句（提炼器不是守门人——不做 keep/reject，无每日上限， 提不出稳定结论给空串跳过）；
  • 四态一致性裁决后入事实层，写齐 source_kind / observed_at / provenance / context_key；
  • 幂等键 = 观察 record_id 存 atoms.source_task，重跑不重复；
  • 在日记步之前跑——升格产物当轮即可被日记素材引用。

实测：20 条（11-09 旧观察 + 11-10 memory_observe）→ 20 stored；11-13 再升格 11 条、去重合并吸收 2 条。

RAG 链路（召回与向量臂）2026-11-14 重写 · 含叙事层向量

检索入口有三池：L1原子记忆（search_brain）、 L0原话与见闻（search_l0）、 叙事场景块 / 日记 / 月记 / 关系卡（search_narrative）。 每一池都是 词法（FTS/bm25）+ 向量（bge-m3 · 1024 维余弦）双通道并行， 向量只做候选生成、不语义化排序：排序永远走既有的「相关 × 重要 × 新鲜」公式。 下面的 5 步是这条链路的全部，参数与实测数字在 ②③⑥⑦。

① 查询进来先做什么

  • 不改写问句：用户原话直进。词法通道用 _query_terms 产「2 字滑窗短语 + ASCII token」 （BV 号、型号、店名、牌子这类精确串），FTS 用它们 OR 起来再叠 2 字 LIKE 兜底；向量通道只用整句。
  • keyword 为空 → 整体不走向量：没有可依赖的词面锚点时，语义通道单独存在只会灌水，这是硬闸。
  • 词法侧的 glue 词过滤（「那个/就是/怎么」这类）不作用于语义行——语义行本来就不靠字面重合。

② 候选生成：三池 × 双通道

为什么叙事 floor 不是 0.58：叙事向量建在 400 字摘要上，目标条目 cos 实测只有 0.499–0.686（比 atom 卡片低一档）。真库副本扫描：0.58 → 硬改写命中 8/11、 0.55 → 8/11、0.52 → 9/11 且负样本噪声不变、0.50 → 命中不变但噪声 +1。故定 0.52。

③ 融合：rel 怎么来，final 怎么算

rel      = bm25 原值（词法行）        ｜  cos（向量专属行，rel_mode=cos 缺省）
final    = 0.55·rel + 0.30·salience + 0.15·recency        # rank_weights，可配
进注入面 = final ≥ 0.30（inject_floor） 且 通过去冗余 / 轮换环  →  取 top_k = 5
  • 两路同命中一条：保留 FTS 行的 bm25 rel，避免同一条被计两次；叙事池因为整体重载每行 （近因浏览候选 rel=0），向量行必须按 key 升级 rel（取 max），否则永远撞 seen、通道形同虚设——这是本轮踩过的坑。
  • rel_mode=calib（cos 标定到 bm25 量纲，rel = 0.296·cos + 0.665）：46 条实测净收益 0（一条换一条）、代价新增行 +10 / FTS 行掉出 +10 → 缺省关。
  • quota=N（语义保底席位，三道门：有效词 ≥4 / 无 ASCII 精确 token / 最强 cos ≥0.62）： 实测命中提升 0（cos 够得着的本来已进 top5）→ 缺省 0。
  • 剩余 miss 与同域硬负共用 0.58 附近的分数区间：纯阈值 / 配额只能互换、无法双赢，要同时解决 须引入内容感知判定（cross-encoder 重排），归 phase 2。
为什么必须有 cos_floor：final 公式里 importance/recency 两项会把任何向量专属行 抬过 0.30 的既有 floor（cos=0 也拿 0.30 基础分）——没有语义下限，无关查询也会被塞满 k 条。 atom 定 0.58 的实测依据：同域硬负 4/4 → 1、新增行 37 → 18、语义命中 19/21（0.52 亦 19/21， 但硬负不降）。L0 抬到 0.58 会直接丢行（正确行 cos 实测 0.546），所以分层。

④ 索引怎么保持新鲜：欠账模型 + 两处自愈

  • 写路径零嵌入开销：主写不同步嵌，只算 src_hash；文本/模型变更即「欠账」。 回填三来源——writer worker 线程批嵌、查询前 lazy 补（atom/L0 ≤10 条或 ≤2s 预算帽；叙事 ≤8 条/轮， 独立预算不抢前两池）、scripts/backfill_vectors.py。
  • 比对方式随表形态：L0 / atom 是追加型 → 行号水位线；叙事是覆盖更新型（幂等键 kind|doc_id）→ 全表 src_hash 比对，水位线对覆盖场景无效。
  • 删除即清理：删场景块 / 删 L1 时连带删 vectors + fts 行，不留悬空指针。
  • 读时修：read_narrative 读到空正文（文件被手动删走）→ 当次顺手撤索引 + 向量， 单行 DELETE、约 1ms、只在命中时触发，不进会话主路径。
  • 后台扫：巩固线程内 _reconcile_narrative_index(20) 对账 + _prune_orphan_vectors(50) 清三通道孤儿（限量、幂等、失败静默）。检索侧本来就 JOIN 源表、脏行命中不到，这两处只为治「无声膨胀」。
  • 没有 CLI 重索引入口：_rebuild_brain_schema 是 DROP 整库（仅 schema 版本不符时触发）， 不可当重索引工具；手动改文件后的正解就是上面的「读时修 + 后台扫 + 回填」。永不删用户的 md。

⑧ 已知边界

  • 叙事只做 doc 级：向量覆盖 400 字摘要，能答「哪一天/哪一块相关」，答不了「该文档某个细节」—— 细节级要 chunk 级索引，属 phase 2（world 设定库一起设计）。
  • 摘要质量即召回上限：硬样本仍漏 2 条（目标 cos 0.499，够不到 floor），是摘要信息密度问题，不是索引问题。
  • 不做 cross-encoder 重排：CPU 下 0.3–3s/查询，收益与延迟不划算，phase 2。
  • 在线检索仍共用 120s 超时：sidecar 卡住时最坏等 120s，建议检索路径单独 5s + 降级断言（未拍板）。
  • 自动合并首次生效前先看一轮 jsonl：合并可逆，但语义判断值得先扫一眼。

L2 · 场景块

projects/<pid>/memory/scene_blocks/*.md——按主题组织的蒸馏块 （META + 正文，软 1500 / 硬 4000 字符，读取端不截断）。scene_index.json 是投影缓存，承载时间节流位与进料游标。

  • 进料 = 游标后的 active 原子增量（一池不分组，INV-9）；严格 L1 下增量来自 显式记与升格产物——无增量整轮跳过 LLM，这是场景块不无限长的主闸；
  • 维护 = 带工具的 agent 循环（白名单 scene_read/write/edit，≤32 迭代 / 墙钟 300s）， UPDATE > MERGE > CREATE，容量三级预警（max_blocks 15）；
  • 游标复合键 updated|record_id；五种不推进：零增量 / 出错 / 无 LLM / 空抽取 / agent 零动作——不让「喂了但没人吃」的批次被划过去；
  • 带外信号 [PERSONA_UPDATE_REQUEST] → 下次巩固强制画像重写；
  • 索引与向量（2026-11-14）：场景块与日纪/月记/关系卡同一套 narrative_index + narrative_fts，向量建在 400 字摘要上 （source='narrative'，键 kind|doc_id，floor 0.52）；正文永不进索引 （INV-12），读取走指针 + 读时修（正文没了就撤索引）。详见 RAG 链路 ②④。

L3 · 自我画像

memory/self_profile.md（全局一份）——<self-persona> 随 system 全局注入。巩固期蒸馏（新增 active 原子 ≥20 或带外信号强制），LLM 增量重写、 旧版自动备份 .bak；助手的应对策略/拒绝规则一律不入画像。三分法之后： 自身=self_profile，人=关系卡（含用户卡），世界=atoms 召回。

巩固周期（consolidation ·「睡觉时整理」）

flush_brain 收尾调 maybe_consolidate：后台线程、派发闸防重复。 触发 = flush_count ≥ 20 或距上次 > 1 天。

巩固线程还兼三件索引维护（2026-11-14 落地，都限量、幂等、失败静默，不进会话主路径）：

  • dedupe_atoms(apply=True, max_merge=10)：同 kind 字符 bigram Jaccard ≥ 0.85 合并； 向量就绪时叠加 cos ≥ 0.95 判「换了说法」的重复；cos 0.80–0.95 且字面差 → 只报告不合并 （落 memory_dedupe-*.jsonl）。合并可逆：dup → tombstone + superseded_by，原文不删。
  • _reconcile_narrative_index(20)：叙事对账——索引行在、正文文件没了 → 撤 index + fts + 向量 （每轮至多 20 行）。
  • _prune_orphan_vectors(50)：清三通道（atom / l0 / narrative）指向已删记录的孤儿向量。

日记系统（叙事层主形态）

全局一篇 memory/diary/diary-<日期>.md——巩固期 D+1 写昨日 （幂等键=日期，补齐最近 7 天），素材跨项目聚合、一次 LLM 生成。正文 ≤1800 字， 本体不进注入面（INV-11），索引只存 summary+topics+atmosphere（INV-12）。

关系卡（「记得某个人」）

memory/relations/<uid>.md 全局一份、按人存（同一个人跨群/私聊不裂）。 用户卡用合成 key master（多账号归一：每个账号各自一个 uid，卡内合成同一个 key）， 卡名 name: <owner>——名字的唯一宿主是卡（identity 读卡 META， 无卡/无 name 回退缺省；配置零参与，这是「由记忆驱动」而非「由配置写死」）。

  • L0 直驱（2026-11-10）：_flush_tail 按 speaker 行跨场合聚合，新增 ≥12 行或 距上次 ≥600s 触发；每人 ≥3 条往来才写卡、每轮 ≤5 人；不产原子的轮次同样能更新 （空 atoms 库不挡路）——印象卡随对话持续生长，与巩固周期解耦；
  • 结构：META(name/uid/topics/we) + 正文三行「最近交手 / 他对助手的态度 / 助手对他的态度」； 用户卡多一段【稳定背景】（LLM 丢失时代码补写回，静态字段归入此类）；
  • 检索资产：通道自动注入已物理删除，由 narrative_search(peer=) 按需自取； 外部来源读卡只给 summary（N-10）；
  • 规模治理：无上限无 TTL（2026-11-04 裁定暂不动——加淘汰会撞 P7「不做衰减」）。

语境链（circle_note · 场合化表达预期）

载体是语境预期（这个场合聊什么、什么分寸、共同话题词面），不是可引用事实：

  • flush_brain 收尾把消息按场合累积进 context_buffer（话题词面 2 字滑窗高频，零词表零 LLM；不写他人原话）；
  • 阈值（12 条或 600s）触发一次 reflection → circle_note （summary ≤160 字 / topics 2-6 / tone ≤40 字），重写不追加、失败保留旧版；
  • 消费：只影响 <current-context> 与检索排序（w_bg ×1.10）； 永不进 atoms、不进对外发话（INV-5/INV-10）；
  • 每场合每周期 ≤1 次、全局 ≤5 次；老场合冷启动走巩固 9.5 步。

写入通道红线

不变量（防回退红线 · 14 条）

1 静态内容禁止每步重发——尾部注入包装已删，回流即违规（R4 锁）。
2 L2 全文唯一入口——read_scene_block 只在 scene_executor；注入面只准索引条目。
3 意图门零格式字面量——畸形调用识别全 LLM，内核零厂商格式标记。
4 检索结果永不自动注入——L1/L0/叙事只经工具；例外清单清零。
5 一条记忆在 atoms_fts 恒为一行——_fts_upsert 唯一写通道；读链只取现行文本。
6 合并只在同一适用域——跨域一律 novel；超 200 字拒并；绝不静默截断。
7 单库单人格（INV-1）——L1 与 L3 全局唯一，persona 过滤已移除。
8 场合不是分区键（INV-2）——context_key 只做信号/标注，不建表不拆库。
9 加权不过滤（INV-3）——场合/圈层/peer 三类信号只改排序，不得变成 WHERE。
10 事实与语境分离（INV-5）——circle_note 不参与四态、不进对外发话。
11 事件 → 助手的取舍 → 记忆（INV-6，2026-11-10 重写）——收尾零自动提炼； 外部可达见闻永不升格；禁止回流任何按来源一刀切的准入开关及其伪替代。
12 叙事正文不进注入面（INV-11）——正文只经 narrative_read 按需读。
13 叙事索引只存指针（INV-12）——search_text 只含 summary+topics+atmosphere。
14 观察与对话分道（INV-13/14）——capture_observation 唯一观察入口；出处必填、只作追溯。
