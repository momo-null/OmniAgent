1. 产品定位

OmniAgent 是什么、为谁服务、与过去版本的根本区别。

它是什么

一个 通用自主 Agent 内核：模型通过调用工具完成任务，能做什么完全由外层插件（自研 tool + 外部 MCP）提供的工具清单决定，内核不绑定任何场景。核心范式 = 在线强模型作规划/反思（大模型）+ 本地快模型作执行器（高频决策 / 感知）+ 知识库自学（world-model / skill）。控制流归大模型，程序退化为工具运行时。GUI / 设备操控仅是我的一项特色能力（经外层插件动态注入），而非 agent 的预设身份。

当前主场景

GUI / 设备操控（Android 模拟器经 uiautomator2 / ADB 操控，或宿主机键鼠）是当前用得最多的场景，但 agent 本身是 通用 agent，不 GUI 特化：能力来自外层 tool 插件（截图 / 点击 / OCR / 模板 / 视觉）与运行时自学，不为任何 app / 游戏 / 界面写专属程序。System prompt 已泛化为「通用自主 Agent」，不把「操作电脑设备 / 点界面元素」等写死成 persona——这些只出现在 tool schema 里，由模型按需自主调用。

与手搓态的根本区别

手搓态（2026-07）的死穴 = ReAct 循环、function-call 协议、工具派发全自己写，每加一个能力都要改内核、极易写死。框架态彻底把循环驱动 + 协议 + 工具路由交给 LangGraph / Agents SDK（开源 function_tool 隔离四跳），内核退化为「配置 + 钩子注册中心」；工具实现全部外移至外层插件层——自研 tool（屏幕/鼠标/视觉/文件 IO 等基础能力，用 function_tool 承载）与外部 MCP（开源/第三方系统，纯配置接入）平级，领域逻辑只在外层插件内。

能力边界：图形界面（自绘 / 空间布局 / 图标密集）是关系型 / 状态型的，纯 OCR 文本识别无法理解 UI 元素间的关系与语义 → VLM 作主感知层，OCR 降级为精确坐标 / 文本校验辅助。

2. 核心原则与红线

七条不可偏移的原则。它们是后面所有技术选型的总依据，也是代码审计的「嗅觉测试」。

  1. 控制流归大模型：模型规划任务并决策调用工具（截图 / 点击 / OCR / 模板 / 视觉），程序退化为工具运行时（框架薄壳接管循环）。大模型只在决策点 / 子目标边界低频调用。
  2. 知识自学，无插件：world-model + skill 由 agent 运行时观测积累；场景知识（如 IME 处理、开程序原语）属运行时知识而非硬编码。旧插件系统已丢弃，不迁移。
  3. 能力 == 插件（红线）：内核只负责通用闭环驱动（框架接管）+ 后处理钩子，不认识具体 X；加能力 = 加一个外层 tool 插件 / 接一个外部 MCP，绝不改内核。自研 tool 与开源 MCP 完全平级，由 LLM 直接调用。
  4. 模型无关：能力声明来自模型元数据，动态注入提示词；换 VL / 换执行模型零代码改动。比主流静态工具列表更严谨。
  5. 大模型低频、本地高频：在线大模型仅决策点介入；本地执行器在子目标内自闭环。依据 OSWorld 实测——顶级 agent 75–94% wall time 花在规划 / 反思 LLM 调用，故该延迟设计正确；grounding 是头号失败点 → SoM 必要。
  6. 诚实边界：自学习只长「知识 / 策略」，不长「硬件 / 工具精度」；新 skill 须连续成功 N 次才晋升，防幻觉 skill 自欺（自学习 ≠ 自欺）。
  7. 超长任务连续性：把「工作上下文」（有界、可压）与「会话连续性」（外部、持久）分离——无状态大模型 + 持久 world-model + 子目标检查点，使小时 / 跨天任务不丢目标、崩溃可续。
红线（代码嗅觉测试）：改动若给 agents/ 核心加了针对某 app / 游戏 / 任务的判断 → 必须抽成 MCP 工具 / skill。审计约束（scripts/review_lint.py）：C1 工具零写死（内核不出现工具名分支）、C2 字段零假设（内核不出现屏幕/ocr/active_window 等感知字段）、C3 模型无关、C4 钩子自治（L2 单步自愈、仅抛锚才呼叫人工）、C5 HITL 双通道（硬停止 / 软注入，目标：全用框架原生；当前仍为自研，见 N10 待办）。

3. 技术选型与决策依据

所有关键技术决策与「为什么这么选、落选方案为何被否」。均为当前落地态；未编码项明确标注为待办，不伪装成已完成。

维度当前选型决策依据（为什么 / 落选方案）
编排 + 单 agent 运行时 LangGraph（编排）+ OpenAI Agents SDK（ReAct/FC/流式/MCP 加载） 手搓 ReAct/function-call 协议成本高、易写死 → 交框架原生。两者协同非二选一：LangGraph 表达 Manager/Worker 多 agent 拓扑与 handoff，Agents SDK 跑单 agent 循环并从 MCP 加载工具。P0 框架优先：interrupt / 运行时消息注入 / 状态机全用框架原语，不自研。
在线大模型 任意 OpenAI 兼容接口模型（base_url / model / api_key 配置） 本地算力不足 → 不能靠本地模型当大模型；在线强模型做规划 / 反思；走 OpenAI 兼容接口，模型可任意替换（仅改三项），不绑定任何厂商。作为 SDK 的 Model provider 接入，守住 C3。
本地执行模型 任意本地 VLM（OpenAI 兼容 / llama.cpp 等，由 config 指定） 有云端大模型后本地只需快速执行 → 选轻量 VLM；要求「一个模型干文本 + 视觉」、离线可用、零架构改动。模型可任意替换：具体选型由 config.yaml 决定。
执行后端（设备） 自研外层 tool 插件（屏幕/鼠标/键盘：Host/Emulator 控制） 原 execution_host.py / execution_emulator.py 实现平移为自研外层 tool（function_tool 承载），工具 = 现有 tool_schemas（type/click/observe/launch_app…）。内核只持「工具名列表 + 能力分组配置」，零实现。B2 的 text_of/verify_done 抽象 → 外层 tool 内 get_state_text + verify 语义。
视觉通道 自研外层 tool 插件（SoM + VLM 工具 + yolo 内部原语） RPG UI 关系 / 空间 / 图标密集 → VLM 作主感知；SoM 编号标注提点击可靠性；OCR 降级精确文本 / 坐标；yolo 仅作 SoM 内部原语（默认不单独暴露，工具=插件原则下可直调）。SoM marks 跨步状态自持于 tool 内 som://last_result resource，内核零感知（α 决策）。
工具解耦 外层插件（自研 function_tool + 外部 MCP，二者平级） 红线「能力 == 工具」升级为「能力 == 平级插件」：加能力 = 加自研 tool 或接外部 MCP，core 零改动；开源 function_tool 隔离「定义→注册→派发→回填」四跳，框架原生 dispatch，内核不再持有 ToolRegistry 与 if name== 分支（C1 自然清零）。MCP 本质是对外协议，仅用于外部工具接入。
Python 执行 自研外层 tool 插件（run_python，待 M0 后补） 补齐纯文本能力缺口（手搓态无脚本执行）；沙箱 / 超时 / stdout 捕获。作为外层 tool 接入，与 MCP 平级，无需手搓。
知识库 / 护城河 world-model + skill 库（Hermes 风 Markdown + YAML）+ Trajectory + Curator 框架外保留，作为生命周期钩子挂载：每步后处理 → trajectory.log；任务结束 → Curator.run_once()；成功轨迹 → SkillLibrary 提炼晋升。L2 对循环有单步自治权（C4），但协议层仍归 L3。自学无插件。
自升级 meta-loop 四层：skill（知识）/ world-model（精炼）/ strategy（反思）/ weight-level（训练链升级路径） 知识级管行为适配，权重级管执行器能力适配，互补非互斥；权重级触发策略 A（阈值 + 提示确认，不自动跑）。旧 LoRA 链保留为主动升级路径。
持久化策略 三级留存：raw 轨迹 / failures / gguf 当前 + 上一版 采集常开（仅多写 jsonl，近零成本）；防低质轨迹稀释 SFT 语料；存储敏感。
验证门 N = 3（候选 skill 连续成功 3 次晋升） 防「乱点 20 次最后成功」被学成策略；幻觉 skill 自欺护栏。
Curator 触发式（任务完成后跑一次） 静默维护技能库锐度（prune + refine + 标 low-quality）。
上下文管理 worker：history_keep:3 硬滑窗；大模型：long_task 自动压缩（token 占比主触发）；超长任务：无状态大模型 + world-model 落盘 + 子目标 checkpoint 1M 窗口 ≠ 不压（context rot）；本地执行器无摘要能力 → 硬裁是唯一选择；大模型不做 3 轮（会丢全局上下文）。压缩 / 滑窗策略由框架 lifecycle 钩子执行，owner 变框架。
Escalation 阈值 verify 连败 3 / 内层 8 步 / 无置信硬触发 / 显式 escalate / ctx 溢出 / subtask 墙钟 120s（调试，待实测回收 60s） 全放 config.yaml 不硬编码；前沿无先验最优，默认值先跑通再测反推。handoff 表达为 LangGraph 原语（N6）。
HITL（人工干预） 双通道（硬停止 /stop + 软注入插话），全用框架原生 长任务少干预诉求：人工只在「抛锚（超阈值无法自愈）」介入，日常自愈由 L2 兜。硬停止 = 框架 cancel 当前 run + 新指令重启；软注入 = 运行时 push user 消息，下一步 agent 可见、优先级高于 L2 自治。前端 SSE//stop/插话已存在（手搓态 N10），迁框架 interrupt 接管（C5）。
架构红线（零场景特化）：核心执行层不写任何 app / 游戏 / 业务专属策略；所有「怎么做」的任务流程知识由 skill / 知识库提供、由模型决策，不进执行器代码。内核经 review_lint.py 守护 C1–C5 五条契约。collect_list 作为通用工具（批量抓当前列表）保留；枚举类任务在「纯框架 + 无辅助代码」下能否由本地执行器自主完成，是待验证的架构通用性边界。

4. 行业对标与参考

框架态设计与 2026 主流 agent 范式高度对齐。下列参考是「为什么这么选」的外部佐证。

范式 / 项目与 OmniAgent 框架态的对应关系
MCP（Anthropic，2025-12 捐 Linux Foundation AAIF）事实标准「AI 的 USB-C」；哲学「build once as MCP server, any host 可用」= 我们的「能力 == 工具、core 不认识 X」。工具全经 MCP 接入，框架原生加载。
ReAct（tool-use loop）2026 单 agent 默认范式 = 我们的通用闭环，现由 OpenAI Agents SDK 原生接管，不再手搓。
Agent Skills（Anthropic 开放标准）SKILL.md 文件夹、agent 像装 App 加载技能 = 我们的 skill / world-model 纯文本知识库。
Hermes Agent（NousResearch，MIT）自进化技能系统 + Autonomous Background Curator；三层记忆本地 markdown；轨迹导出供微调。直接印证「world-model + skill 自学」范式，skill 格式对齐 agentskills.io。
UI-TARS（ByteDance）原生 GUI 模型；System-2 Reasoning + Iterative Training w/ Reflective Online Traces。印证「反思 + 从失败学」须内建。
MGA（Memory-Driven GUI Agent）本地快 VLM 感知 + 远程强模型记忆规划 ≈ 两层架构的论文版，强印证。
OSWorld 基准真实电脑环境 369 任务；顶级 agent 75–94% wall time 花在规划 / 反思 LLM 调用 → 印证「大模型低频、本地快执行」；grounding 是头号失败点 → SoM 必要。
LangGraph / OpenAI Agents SDK协同栈：LangGraph 编排多 agent 拓扑 + handoff + interrupt（HITL），Agents SDK 跑单 agent ReAct/FC/流式并从 MCP 加载工具。印证「循环与协议交给框架、领域脑外挂」。
诚实 caveat：纯自主无结构化路由是科研前沿，生产普遍加 guardrail（step limit / tool allowlist / plan-replan / Reflexion 防循环）——OmniAgent 定位研究探索 agent 可接受，但保留 step cap。自动生成 skill 当前仍不可靠（弱模型 skill 会放大 bug），故「人审核接入」是正确保守姿态而非妥协。

5. 维护约定

维护纪律（关键）：本文件描述 当前框架态。设计变更时在此「就地更新当前状态」，不追加演进史段落。模块名锚定实时代码树（omni_core/ 内核 · omni_core/tools/ 外层插件包 · devices/ 设备驱动 · model_hub/），改代码后同步此处。框架态核心转变：ReAct 循环与 function-call 协议交由 LangGraph + OpenAI Agents SDK；工具脱离内核、成为外层平级插件（自研 tool 承载基础能力 + 外部 MCP 承载外部系统，二者平级、由 LLM 直接调用）；护城河（WorldModel/Curator/Trajectory/Skill）外挂为生命周期钩子。
