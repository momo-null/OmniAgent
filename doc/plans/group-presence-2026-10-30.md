# 群聊自然存在感（Group Presence）设计 v1

状态：M1–M3 已实施（2026-10-30，未提交待验收；M4 彩蛋未做）。实现落点：
`gateway/group_presence.py`（判定层，通道无关）+ `gateway/channels/napcat.py`（接线）+
`gateway/channels/base.py`（InboundMessage.origin）。测试：`tests/test_group_presence.py`。
关联：`doc/agent-control-master-spec.md`（单链纪律）、`gateway/channels/base.py`（通道契约）

## 1. 问题与目标

现状：QQ 群只有 `require_at` 一个布尔门——消息要么触发要么丢弃，只有两个极端：只回 @（像个工具），或全收（刷屏机器人）。

目标：

1. **被点名必回**：@、引用回复 bot、文本点名，急迫且确定；
2. **自然接话**：bot 参与过的对话有人跟帖（即使没 @）能接上；群消息波次里出现值得回应的点，能自然插一句；
3. **克制在场**：主动发言有预算有节奏，沉默是默认态，绝不刷屏。

非目标：

- 不做多群人设（人格实体绑槽，单人格全表面）；
- 不做营销式主动推送、跨群广播；
- 不新增记忆旁路——群消息的长期沉淀仍走既有 state_text / 写链价值判约定；
- 内核（omni_core）零改动。

## 2. 核心原则：要不要说话 ≠ 说什么

开口判定是**纯通道侧计算**（结构特征打分 + 说话预算，零 LLM、微秒级、可解释、可热调参）；说话本身走唯一主链。开口判定是 `require_at` 的模糊化：无状态、fail-silent（判错永远往安静倒）、只做一件事——把「这条消息归不归我管」从精确规则换成概率判定。判定通过的波次升格为普通 `InboundMessage`，走与 @ 完全相同的网关分发链路，不造平行管道。

## 3. 三档分层

### 3.1 T0 被点名（确定性触发，急迫路径）

| 触发 | 判定 | 备注 |
|---|---|---|
| @ bot | at 段解析（现有） | 不变 |
| 引用回复 bot | reply 段取被引 message_id → `get_msg` 展开原文 → 被引者是自己 | 展开为 `[引用] 昵称: 文本` 行随正文进上下文，模型必须知道对方在接哪句 |
| 文本点名 | 正文命中昵称/别名表（配置） | 没打 @ 的自然呼叫 |

T0 **不经过防抖与打分**，直接进主链（被点名无等待）。合并转发展开后置（M4）。

### 3.2 T1 旁听与开口判定（每群一份状态）

未命中 T0 的群消息不再丢弃，进入旁听缓冲：

```
WaveBuffer（每群，内存态，重启即清）:
  msgs: [(ts, speaker, text, is_own, reply_to)]   # text 为文本投影，媒体用占位
  上限: 12 条 × 10 分钟，双重滚动
```

**防抖合并器**（波形 → 决策时点；多条消息只做一次决策）：

- 静默窗 2s：新消息重置计时；同作者连发 +0.5s；
- 纯媒体消息至少等 4s（看图/表情需要时间）；
- 单批上限 8s：再吵也别攒太多；
- 被点名消息走 T0，不受此等待约束。

**结构打分**（逻辑回归，对波内最值得回应的一条打分；特征全部 O(1)，窗口=最近 5 条 / 300s）：

| 特征 | 含义 | v0 权重 |
|---|---|---|
| intercept | 基线 | -1.2 |
| mention_name | 正文提及 bot 名/别名 | +1.5 |
| at_other | @ 了别人 | -1.1 |
| has_question | 疑问句 | +0.5 |
| placeholder_only | 纯图/表情/转发无文本 | -1.0 |
| recent_self_ratio | 最近 5 条里自己发言占比（对话进行中则延续） | +2.0 |
| recent_count | 窗口内消息条数（刷屏抑制） | -0.04 |
| log1p(silence_sec) | 距自己上次发言秒数（沉默越久越可能冒泡） | +0.05 |
| pending_count | 本波积压条数 | +0.1 |

**v0 权重仅为量级占位，上线后由判定日志重拟合替换**（见 §7）。

**说话预算门**（把话痨度变成动态阈值，防刷屏主保险）：

- `talk_value ∈ [0,1]`（每群可覆盖）→ 每小时目标主动句数 N；
- 1h 滑动窗维护：expected（各波评分之和）、forced（被点名期望回复数，每次 @ 计 0.9）、actual（实际主动发言数）；
- keep_ratio = 前馈 `(target−forced)/expected` × 反馈 `max(0, 1+(target−actual)/max(1,target))`——说超了自动收紧；
- 阈值 = 按 keep_ratio 对评分分位截断（等价「只回 top-k 条」）；样本 <20 退静态阈值表；
- 主动发言与被点名回复共享同一预算，但被点名只计数不设闸。

**线程热窗口**：bot 最近 15 分钟内发过言 → 该群阈值下修一档（参与中的对话跟得住）；窗口冷却后回常态。这是「自然接话」的主要来源：自己抛出的话有人接，跟帖波次的评分天然带上 `recent_self_ratio` 加成。

**升格**：判定通过 → 组装 `InboundMessage`：

- 场合自述变体：「没人点名你。群里刚才在聊：〈波次摘要〉。你自己判断要不要说话——想接就调 msg_send_*，觉得时机不对就什么都不做。」
- 波次文本全部携带不可信外部输入标记（现有约定延伸到升格路径）；
- `reply_mode="explicit"` 不变——**模型保留最终沉默权**：门只提名，不代言。

### 3.3 T2 节制器（防刷屏的硬约束）

| 机制 | 规则 |
|---|---|
| 意愿经济 | 主动发言一次扣 w；每分钟沉默回补；低于低水位禁止主动（被点名不受限） |
| 连续抑制 | 连续 2 次主动发言 → 下次主动判定概率减半；连续 3 次 → 禁止主动（防自激） |
| 空闲退避 | 连续判定「潜」按 base×2ⁿ 退避（封顶 5min）；本波积压 ≥6 条立即旁路退避（群里吵起来了别睡） |
| 硬闸 | 每群每小时主动 ≤3（配置）；安静时段不主动；bot 两次主动发言之间必须插有他人消息 |
| 频控 | 每 chat 30 条/分钟滑动窗（防恶意刷，T0 也在内） |

情绪周期（后置彩蛋，M4）：每群随机在活跃期（3~4 分钟）/ 潜水期（10~20 分钟）间切换，潜水期主动判定一律拒绝——带来「今天话多/今天话少」的长期人格感。

### 3.4 出站自然度

- **打字延迟**：按字数 0.3s/字（中文）计算延迟后发送（上限 8s）；单字短回 ×3（迟疑感）；
- **分条发送**：按标点切 1~3 条、间隔随长度——人类发消息是几条短的，不是一篇长的；现有 `chunk_text` 1200 硬分条保持为最后兜底；
- 发送失败重试一次后放弃：T1 主动消息**不补发**（宁可少说一句）。

## 4. 代码落点

```
gateway/group_presence.py      # 新模块，通道无关：WaveBuffer / 防抖 / 打分 / 预算 / 节制器
gateway/channels/napcat.py     # 接线：T0 判定扩展、未命中消息喂 buffer、引用展开、昵称净化
gateway/channels/base.py       # InboundMessage 增加可选字段 origin: "named" | "wave"（dispatch 日志区分用）
```

- **昵称净化**：昵称/群名片进场合自述与旁听缓冲前，白名单字符集 + 剥控制字符 + 32 码点上限——群昵称是攻击者可控字段，防伪造前缀与边界标签（注入面）。
- **与 barge-in 语义衔接**：升格回合到达时若 bot 正在出回合中，走既有「注入为主、排队兜底」路径，不新增机制。
- **require_at 交互**：群启用 presence 后，未命中 T0 的消息进 buffer 而非丢弃；未启用群行为完全不变。

## 5. 配置（channels.napcat.group_presence）

```yaml
group_presence:
  enabled_groups: []        # 缺省全关，显式开启才生效
  talk_value: 0.3           # 话痨度 0~1（每小时主动目标约 1~6 句）
  quiet_sec: 2.0            # 防抖静默窗
  batch_cap_sec: 8.0        # 单批上限
  thread_hot_min: 15        # 线程热窗口
  hourly_cap: 3             # 每群每小时主动硬闸
  quiet_hours: "01-08"      # 安静时段（不主动，被点名仍回）
  aliases: []               # 文本点名别名
```

## 6. 分期

| 期 | 内容 | 交付判据 |
|---|---|---|
| M1 | T0 完整：引用展开、回复触发、文本点名、昵称净化 | 引用回复不 @ 也能接住，且模型知道引用内容 |
| M2 | 旁听缓冲 + 防抖 + 打分 + 预算门（单群试点，判定日志全开） | 试点群一天内：主动发言 ≤ 预算、接话自然、无自激 |
| M3 | 节制器全套 + 线程热窗口 + 打字模拟/分条 | 观感「像个克制的人」 |
| M4 | 彩蛋：情绪周期、合并转发展开、表情包 | 均独立可砍 |

## 7. 可观测与调参

- **判定日志**（JSONL，每波一条）：群、特征值、概率、阈值、判定、是否升格、**模型最终是否发言**；
- 用途：① 重拟合权重替换 v0 占位值；② 校准 talk_value；③ 否决率异常告警（门在提名、模型总沉默 = 门过松或自述措辞有问题）；
- 指标：每群每小时主动数/预算比、T0:T1 比例、否决率、退避状态。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 门误开（不该接时接了） | 模型否决权 + 冷却 + 试点期人工盯日志 |
| 漏判（该接没接） | 沉默安全；T0 兜底显式场景；日志复盘调阈值 |
| 自激刷屏 | 连续抑制 + 预算反馈收紧 + 硬闸，三重独立 |
| 旁听缓冲成注入面 | 昵称净化 + 不可信标记 + fail-silent |
| 判定成本 | 零 LLM（纯算术），O(1) 窗口，与群活跃度无关 |

## 9. 测试

- 打分函数：特征边界单测（表驱动）；
- 预算门：前馈/反馈收敛、超预算收紧、样本不足退化；
- 防抖：时序用例（静默窗重置 / 单批上限 / T0 急迫旁路）；
- 净化：恶意昵称样例表（控制字符、XML 标签、超长）；
- 集成：napcat 假 WS 事件流回放（T0 / T1 各一组）；
- 测试纪律：按既有约定拆小批 + `--timeout`，不跑全量 pytest。
