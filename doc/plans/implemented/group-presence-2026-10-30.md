## 0. 定位红线（最高优先级，任何设计先过这一关）

- 她是**个人助手**：代表主人在群里说话、替他管群。**不是专门服务某个群的机器人**。
- 因此本层**不得**为群聊新增记忆旁路、也不得以群为界拆人格/拆库/拆 profile
  （2026-11-01 明确否决）。记忆如何归属与加权，见 `doc/plans/implemented/memory-architecture.md` §2.1 / §2.8。

## 1. 问题与目标

原状：群聊只有 `require_at` 一个布尔门——要么只回 @（像个工具），要么全收（刷屏机器人）。

目标三条：**被点名必回**（确定、急迫）／**自然接话**（参与中的对话跟得住、值得接的波次插一句）／
**克制在场**（沉默是默认态，有预算有节奏）。

非目标：多群人设、营销式推送、跨群广播、新增记忆旁路、内核（`omni_core`）为群改造。

## 2. 核心原则：要不要说话 ≠ 说什么

开口判定是**纯通道侧计算**（结构特征打分 + 说话预算，零 LLM、微秒级、可解释、可热调参）；
说话本身走唯一主链。判定通过的波次**升格为普通 `InboundMessage`**，与 @ 完全同链，不造平行管道。
判定本身无状态倾向、fail-silent（判错永远往安静倒）。

## 3. 三档机制（现行实现）

### 3.1 T0 被点名（确定性，不经打分）

| 触发 | 判定 | 备注 |
|---|---|---|
| @ 自己 | at 段解析（`self_id` ∈ ats） | @ 别人**从不** T0 |
| 引用自己的消息 | reply 段 → `get_msg` 展开 → 被引者是自己 | 展开为 `[引用] 昵称: 文本` 行随正文进上下文 |
| 文本点名 | **仅正文**命中昵称/别名（引用行不算呼叫） | 撞名用「严格超集遮蔽」：他人名片严格包含自己名字才遮，完全同名的裸名不遮 |

T0 不经过防抖与打分；被点名必回，但**模型保留最终沉默权**（不调 `msg_send_*` 就不发）。

### 3.2 T1 旁听与开口判定（每群一份状态）

- **旁听缓冲**：`12 条 × 10 分钟`双滚动，媒体用占位符；昵称先净化（剥控制字符/标签、32 码点）。
- **防抖合并**：静默窗 2s（同作者连发 +0.5s）、纯媒体 ≥4s、单批上限 8s。
- **结构打分**：9 个 O(1) 特征（mention / at_other / 疑问 / 纯媒体 / 最近 5 条自己占比 / 消息密度 /
  沉默对数 / 积压条数 / 基线），逻辑回归；`_WEIGHT_V0` 仍为量级占位，等判定日志攒够重拟合
  （见本地追踪文档 §B-3）。
- **预算门 v2（线程经济 + 分位 top-K）**：
  - 计费单位 = **轮次**（一次完整互动 = 一轮）：主动开话 / 入场（波次升格）计一轮；
    **同一轮内的接话续聊不计**（15min 热窗）；**被点名回复永远不计**。
  - 口径澄清（2026-11-01 用户确认）：`talk_value` 与 `hourly_cap` 数的都是**轮次**，不是条数——
    「3」= 每小时 3 轮主动互动，轮内可多条。**不要把续聊计入预算**（那会退化成"一小时只说 3 句"）。
  - `target = 10·talk_value`（每小时想开的新话头数）；阈值 = 最近 1 小时波次分降序第 k 高
    （`k = target − 已开线程数`）；预算耗尽 → 0.98；预算花不完 → `wave_floor`（实配 0.35）。
    当前实配 `talk_value 0.3`（**3 线程/小时**，2026-11-01 从 5 回调：修复热窗计费后出现
    「没人接话仍继续主动开口」）、`hourly_cap 3`（线程口径，接话续聊不计）。
  - **冷启动不再有静态阈值表**：任何样本量都走预算门（低流量群自动获得「按 talk_value 节奏接话」）。
- **线程热窗口（15min）**：只下修阈值/豁免退避，**不再作为免费续聊的依据**——
  免费续聊只看「她自己开的话头」（`_last_proactive_ts`），否则点名密集的群会让预算门整体失效。
- **@ 归属**：180s 内有人 @ 了别的成员且被 @ 者已应答 → 不开新话头（`at_other_thread`）；热窗续聊豁免。
- **升格自述**：「没人点名你。群里刚才在聊：〈波次〉。你自己判断要不要说话」+ 不可信外部输入标记 + 身份锚。

### 3.3 T2 节制器（打分前的硬拦截）

意愿经济（0.34/线程，回充约 sustain 10 线程/小时，低水位禁主动）／连续开话守卫（8）／
空闲退避（base×2ⁿ，封顶 5min，热窗豁免，积压 ≥6 条旁路）／每小时硬闸（`hourly_cap`，线程口径）／
安静时段不主动（被点名仍回）／每 chat 30 条/分钟频控。

### 3.4 出站

已实现：显式发送（`msg_send_text/voice`，最终回答不外发）／身份锚／点名回复带引用（**仅文字**，
QQ 对「引用+语音」显示有 bug）／线程级语音模式（话头掷骰、热窗内不换轨、对方明确要求可改判）／
T0 冷却（同人同文 90s）／出站同文去重（同 chat 300s，失败不占位）。

唯一缺口（→ 本地追踪文档 §A-3）：**打字延迟与分条发送未实现**——目前只有 `chunk_text(1200)`
硬切，她永远发「一条结构完整的句子」。

## 5. 配置（`channels.<name>.yaml`）

```yaml
group_presence:
  enabled_groups: []        # T1 主动参与白名单（应为 allow_groups 的子集）
  talk_value: 0.3           # 0~1 → 每小时想开的新话头数 = 10·tv（当前 3，2026-11-01 从 5 回调）
  hourly_cap: 3             # 每群每小时新开线程硬闸（线程口径，接话续聊不计）
  wave_floor: 0.35          # 预算花不完时的最低放行阈值
  quiet_hours: "01-08"      # 安静时段不主动（被点名仍回）
  thread_hot_min: 15        # 线程热窗口（阈值下修/退避豁免）
  aliases: []               # 文本点名别名（登录昵称自动并入）
```

闸门分层：`reply_groups`（群类总闸）→ `allow_groups`（响应范围白名单，空=不限，管 T0+T1）→ `require_at`（触发形态）。
澄清（2026-11-01 定）：**T1 参数全局一份**（talk_value/hourly_cap/wave_floor/aliases/quiet_hours/weights），
**状态按群独立**。
